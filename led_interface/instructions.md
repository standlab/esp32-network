# IoT course — Шаг 2. Индикация состояния и прикладной MQTT ACK

Продолжение первого шага курса. Тот же `ESP32 → Wi-Fi → broker.emqx.io` и те же топики `status` и `heartbeat`.

## Файлы

- `led_interface.ino` — прошивка ESP32 для Arduino IDE.
- `mqtt_sync_client.py` — Python-клиент paho-mqtt 2.x, который показывает телеметрию и отправляет подтверждения.

## Подключение

Три **отдельных** светодиода, каждый **через свой токоограничивающий резистор 220–330 Ω**:

| Цвет | Анод (+) через резистор к GPIO | Катод (−) к |
|---|---|---|
| Красный | GPIO25 | GND |
| Синий | GPIO26 | GND |
| Зелёный | GPIO27 | GND |

Устройство питается от USB. Не подключайте LED напрямую без резистора и не используйте питание 5 В на GPIO ESP32.

## Значения цветов

| Условие | Красный | Синий | Зелёный |
|---|---|---|---|
| Wi-Fi не подключён | мигает | выкл. | выкл. |
| Wi-Fi есть, MQTT нет | постоянно горит | выкл. | выкл. |
| MQTT есть, heartbeat отправлен, ACK ещё нет | выкл. | короткая вспышка | выкл. |
| Последний heartbeat подтверждён Python-клиентом | выкл. | вспышки при отправке | горит до следующего heartbeat |

Зелёный не означает только MQTT-подключение: это проверка ответа **приложения**, которое подписалось на heartbeat.

## Темы MQTT

При `DEVICE_ID = iot-course-node-01`:

| Топик | Направление | Содержимое |
|---|---|---|
| `top-it/iot-course/iot-course-node-01/status` | ESP32 → broker | `online` (retained), `offline` (retained Last Will) |
| `top-it/iot-course/iot-course-node-01/heartbeat` | ESP32 → broker | `{"device_id":"iot-course-node-01","seq":7,"uptime_s":42}` |
| `top-it/iot-course/iot-course-node-01/sync/ack` | Python → ESP32 | `7` — номер подтверждённого heartbeat |
| `top-it/iot-course/iot-course-node-01/command` | Python → ESP32 | `resync` — запросить новый heartbeat прямо сейчас |

Топики создаются из `MQTT_TOPIC_PREFIX` + `DEVICE_ID`, поэтому при смене ID достаточно поменять одну константу в каждом файле.

## Запуск

1. Установите пакет платы ESP32 в Arduino IDE и библиотеку `PubSubClient` в Library Manager.
2. Подключите светодиоды, укажите свои `WIFI_SSID`, `WIFI_PASSWORD` и уникальный `DEVICE_ID` в начале `.ino`.
3. Загрузите прошивку и откройте Serial Monitor на **115200 baud**.
4. Установите Python-клиент: `pip install 'paho-mqtt>=2,<3'`.
5. Укажите такой же `DEVICE_ID` вверху `mqtt_sync_client.py`, запустите: `python mqtt_sync_client.py`.
6. Для проверки зависимости зелёного LED от ответа приложения остановите Python-программу или запустите её отдельно с параметром `--no-ack`.
7. Отправьте команду запроса нового heartbeat: `python mqtt_sync_client.py --resync`.

**Важно:** публичный `broker.emqx.io:1883` предназначен здесь для учебного эксперимента: трафик без шифрования и авторизации, посторонние пользователи потенциально могут публиковать сообщения в те же топики. Не передавайте личные данные и секреты. Используйте уникальные ID устройств.

## Ограничения учебного прототипа

- `publish()` со стороны ESP32 подтверждает успешную постановку пакета на отправку, **не** получение его Python-клиентом.
- Зелёный LED загорается только после прикладного ответа с `seq` последнего heartbeat; при каждом новом heartbeat требуется новый ACK.
- При нарушении связи с MQTT или Wi-Fi статус ACK сбрасывается.
- MQTT PubSubClient с `connect()` может на некоторое время блокировать цикл при попытке установки соединения; бесконечных циклов ожидания здесь нет, поэтому индикация при разрывах работает существенно лучше, чем при `while (...) delay(...)`.
- Last Will `offline` на брокере может появиться не мгновенно после потери Wi-Fi — это зависит от определения потери MQTT-сеанса.
